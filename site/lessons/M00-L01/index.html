Почему программа печатает старый текст?

Вы изменили одну строку в файле и сохранили её. Чтобы понять, что появится на экране, проследим путь этой строки от редактора до запуска. Для первого опыта достаточно браузера.

Пройти опыт по шагам

От строки к работающей программе

Console.WriteLine("Чай"); — инструкция на C#, которая при выполнении печатает слово «Чай». Файл Program.cs хранит написанный вами текст. Сейчас он только сохранён.

Попробовать самому: изменить порядок команд

Здесь вы выбираете действия сами. Начните с готовой сборки, которая печатает «Чай». Добейтесь двух разных результатов запуска. Между запусками поменяйте одно условие и объясните, какое действие обновило DLL.

Повторите опыт реальными командами

В терминале разработчик выполняет те же действия командами. Здесь проект уже создан, а терминал открыт в его папке.

  • dotnet build — собрать проект. Для нашего примера результат включает файл OrderProbe.dll.
  • dotnet run --no-build — запустить существующую сборку, пропустив сборку проекта. Если после сборки вы редактировали исходник, эта команда запустит прежнюю версию программы.
  • dotnet run — подготовить актуальную сборку при необходимости и запустить её. Попробуйте предсказать вывод этой команды сразу после сохранения новой строки.

Для команд работы с проектом нужен SDK (Software Development Kit, набор инструментов разработчика). Готовую DLL можно запустить командой dotnet OrderProbe.dll из папки с результатами сборки. Для такого запуска нашего приложения достаточно совместимой среды исполнения — Runtime — и файлов приложения.

ЭКСПЕРИМЕНТ 01

Соберите среду для задачи

Проект рассчитан на .NET 11. Готовая DLL и остальные файлы приложения уже лежат на машине. Сначала оставьте «Только Runtime 11» и поменяйте операцию на запуск. Затем выберите SDK и попробуйте сборку. Какое изменение позволило собрать исходники?

Глубже: что находится внутри сборки?

В этом консольном проекте компилятор переводит C# в IL (Intermediate Language, промежуточный язык). DLL содержит эти инструкции и сведения о типах. При запуске среда исполнения может преобразовывать методы в машинный код с помощью JIT-компилятора.

Файл проекта .csproj задаёт цель сборки, например net11.0. MSBuild управляет этапами сборки, включая восстановление зависимостей при необходимости. Выбор SDK может зависеть от файла global.json в текущем или родительском каталоге.

Что проверить в реальном проекте

dotnet --version сообщает выбранный SDK. dotnet --list-sdks перечисляет установленные комплекты для архитектуры вызванного dotnet. dotnet --list-runtimes перечисляет среды исполнения. Версии 11.0.100 и 11.0.0 могут относиться к одной установке.

Production. Для веб-приложения может потребоваться ASP.NET Core Runtime. Self-contained публикация поставляет runtime с приложением. Эти два сценария выходят за рамки первого симулятора.

Частая ошибка

После смены Debug на Release команда запуска ищет другой артефакт. При расследовании запишите рабочую папку, TFM и конфигурацию.

Самостоятельная лабораторная

Вы выясняете, почему коллеги видят разный текст при запуске OrderProbe. Начните с пустой папки. Все действия относятся только к этому учебному проекту.

  1. Откройте PowerShell в пустой рабочей папке. Первая команда покажет выбранный SDK, вторая — установленные SDK, третья — среды исполнения. 
    dotnet --version
dotnet --list-sdks
dotnet --list-runtimes
    Запишите версию SDK и строку Microsoft.NETCore.App. Сделайте прогноз: сможете ли вы собрать проект для .NET 11? Если команда недоступна, сохраните первую ошибку для разбора.
  2. Если выбран SDK 11, создайте консольный проект и перейдите в его папку. 
    dotnet new console -n OrderProbe -f net11.0
cd OrderProbe
    В редакторе откройте Program.cs. Найдите текст в кавычках внутри Console.WriteLine и замените его своим первым словом. Сохраните файл.
  3. Соберите проект и запустите его. Запишите слово, которое появилось в терминале. 
    dotnet build
dotnet run --no-build
  4. Замените слово в Program.cs вторым словом и сохраните файл. Сначала запишите свой прогноз для каждой команды, затем выполните их по одной. 
    dotnet run --no-build
dotnet run
  5. Пришлите версии, два слова, прогноз и фактический вывод каждого запуска. Своими словами объясните, в какой момент обновилась DLL. Если среда остановила опыт, укажите команду, первую ошибку и этап, до которого удалось дойти.

Критерий завершения. Другой разработчик сможет повторить ваши действия и объяснить результат по вашим наблюдениям. В M00 оцениваем исходную точку без проходного балла.
