# M00-L02 — От исходника до запуска

**Модуль:** M00 — Среда и диагностика
**Цель:** самостоятельно проследить путь от исходника C# до выполнения готовой сборки на .NET 11.
**Диагностика:** без проходного балла, обязательны собственные наблюдения.
**Материал:** [интерактивный урок](../site/lessons/M00-L02/index.html).

## Начальные условия
.NET SDK 11, PowerShell. Работай в новой папке с консольным проектом TraceFlow, не изменяя работу M00-L01.

## Задание

1. В новой папке выполни:

~~~powershell
dotnet new console -n TraceFlow -f net11.0
cd TraceFlow
dotnet build
~~~

2. Найди фактический путь артефактов в выводе сборки. В стандартной конфигурации это bin/Debug/net11.0/.
3. Выполни:

~~~powershell
Get-ChildItem .\bin\Debug\net11.0\ | Select-Object Name
Get-Content .\bin\Debug\net11.0\TraceFlow.runtimeconfig.json
~~~

Укажи роль DLL и runtimeconfig.json; объясни, что такое IL и метаданные.

4. Выполни прямой запуск:

~~~powershell
dotnet .\bin\Debug\net11.0\TraceFlow.dll
~~~

Запиши вывод.

5. Измени текст в Program.cs на Console.WriteLine("Trace: updated"); и сохрани.
6. Прежде чем запускать, предскажи вывод прямого запуска прежней DLL, затем проверь его. Запиши прогноз и факт.
7. Выполни dotnet build и прямой запуск DLL снова. Объясни цепочку C# → компилятор → IL/метаданные → Runtime → (обычно) JIT → вывод.

## Acceptance criteria

- Есть собственный лог создания и сборки и версия SDK.
- Есть список файлов сборки и содержимое runtimeconfig.json.
- Есть прогноз и факт прямого запуска DLL до и после пересборки.
- Есть объяснение назначения SDK, DLL, Runtime и JIT и отличие build, run, publish.
- При ошибке указаны команда, первая ошибка и последний успешный шаг; не выдумывай вывод.
- Решение объясняется своими словами и переносится на изменённый сценарий.
